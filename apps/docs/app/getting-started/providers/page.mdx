# Providers & API keys

FreeCode sends model requests directly from your machine to the provider you
choose. It does not proxy your API key through a FreeCode service. Pick a
provider and model with `/model` in the TUI, paste the key when asked, and start
working.

The agent behaves the same after you switch providers. That is the point of the
**provider abstraction**: the agent loop depends on one common interface for
streaming text, tool calls, cancellation, and token usage; the provider layer
handles each vendor's API details. See [Provider layer](/internals/providers)
for the implementation.

## What FreeCode supports

FreeCode builds its API-provider catalogue from a shipped
[models.dev](https://models.dev) snapshot, optionally refreshed from a local
models.dev cache. It registers only catalogue entries whose AI SDK factory is
bundled, so a provider shown as supported has a request path rather than a
placeholder adapter.

The six providers below are **featured choices**, not the complete list:

| Provider | Provider id | API key variable | Verified default model |
| --- | --- | --- | --- |
| Anthropic | `anthropic` | `ANTHROPIC_API_KEY` | `claude-sonnet-4-5` |
| OpenAI | `openai` | `OPENAI_API_KEY` | `gpt-4o` |
| Gemini | `gemini` | `GOOGLE_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`, or `GEMINI_API_KEY` | `gemini-3.6-flash` |
| DeepSeek | `deepseek` | `DEEPSEEK_API_KEY` | `deepseek-chat` |
| MiniMax | `minimax` | `MINIMAX_API_KEY` | `MiniMax-M2` |
| Z.ai | `zai` | `ZHIPU_API_KEY` | `glm-5.2` |

For another provider, use `/model` and select it. The catalogue supplies its
provider id, endpoint, SDK family, and accepted environment-variable names.
Not every catalogue provider has a default model: if FreeCode has not verified
one, choose a model explicitly instead of letting it guess a model id.

`gemini-web` is separate from this catalogue. It uses a Gemini web session,
not a metered API key, and is intended for ask/review work. See the model
picker for its cookie guidance and limitations.

## Add a key

The simplest route is `/model`: choose a provider and model, then paste the
key into the masked prompt. FreeCode saves the choice and credential in
`~/.freecode/config.json` with owner-only permissions.

```json
{
  "providers": {
    "anthropic": { "apiKey": "sk-ant-..." }
  },
  "current": {
    "provider": "anthropic",
    "model": "claude-sonnet-4-5"
  }
}
```

You may edit this file yourself, but never commit it: it can contain API keys
and web-session credentials.

### Credential lookup order

For a normal provider, FreeCode checks the provider's environment variables
first, then `providers.<id>.apiKey` in `config.json`. In other words, an
environment variable overrides the stored key, which is useful for CI and for
temporarily using a different account.

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
freecode
```

If neither source contains a key, the error names both the expected variable
and the configuration path. The environment-variable names come from the
catalogue; they are not guessed from the display name.

There is one deliberate exception for `*-coding-plan` variants: their own
stored key is checked before a shared base-provider environment variable, so a
generic key cannot silently select the wrong billed plan.

If you have exactly one configured credential but have not selected a current
provider, FreeCode can use that one. With several credentials, it asks you to
choose rather than guessing.

## Switch models

| Where | How |
| --- | --- |
| TUI | Run `/model` and select a provider/model. |
| Headless | Run `freecode run --model <provider>/<model> "…"`. |
| Config file | Set `current.provider` and `current.model` in `~/.freecode/config.json`. |

A model is pinned when a session starts and persisted with that session. This
keeps later turns from silently falling back to a provider default if settings
change. Model metadata—context window, maximum output, and image support—comes
from models.dev and is used by compaction and attachment validation.

## When a provider fails

The agent loop owns retries and optional provider fallback. SDK retries are
disabled so retry attempts cannot multiply unexpectedly. You can configure a
fallback order in `config.json`:

```json
{
  "recovery": {
    "fallbackProviders": ["openai", "deepseek"]
  }
}
```

A temporary failure may be retried according to the recovery policy. A known
quota-exhausted response is not retried against the same provider; waiting and
resending the full conversation would not help, so FreeCode moves to the next
fallback when one is configured.

## Interview vocabulary

If you are explaining this design in an interview, the key ideas are:

- **Provider abstraction / adapter pattern:** one stable contract hides vendor
  APIs from the agent loop.
- **Dependency boundary:** SDK factories, credentials, endpoints, and request
  shaping stay in `providers/`, not in UI or agent logic.
- **Lazy loading:** FreeCode registers metadata at startup but imports an SDK
  and reads a key only when that provider is first used.
- **Streaming normalization:** provider-specific stream events become common
  text, reasoning, tool-call, usage, done, and error chunks.
- **Resilience:** fetch-layer header and SSE-stall timeouts plus one central
  retry/fallback policy prevent duplicate retry loops.
- **Prompt caching and usage accounting:** stable prefixes reduce repeat input
  cost, while normalized usage keeps billing calculations comparable.
